# Z-Cloud AI v1.6.4 更新说明

> 这一版不是猜的，全部依据你发回来的 `ptp-20261027(2).log`（5.8 MB / 80,724 行）和你截的「属性」面板。
> 先说结论：**上一版两个问题，一个是方向错了，一个是机身限制。**

---

## 一、为什么「刚拍的这一张」一直是空

### 日志给出的硬证据

我把整份日志里所有 PTP 命令数了一遍：

| 命令 | 次数 | 含义 |
|---|---:|---|
| `0x9203` | 241 | 取景帧 |
| `0x100A` | 60 | 缩略图 |
| `0x1008` | 60 | 对象信息 |
| `0x90CC` | 30 | 读优化校准 |
| `0x1015` | 24 | 读属性 |
| `0x1014` | 16 | 读属性描述符 |
| `0x9201/0x9202` | 2 / 2 | 开 / 关取景 |
| **`0x9207`** | **0** | **拍摄** |
| **`0x90C7`** | **0** | **事件流** |
| **`0x1009`** | **0** | **取对象** |

**这一整段会话里，相机一次都没收到过「拍摄」指令。**

### 结论

你是用相机机身上的快门按键按的。那种照片走的是相机自己的存储流程，**不经过 `0x9207 CaptureToSdram`**，App 侧完全不知道你拍过照，所以 `lastCapture` 自然是空的。

之前 v1.6.1 / v1.6.2 我一直在修「回传」链路（句柄解析、写卡重试、兜底下载），那是在修一条你根本没走的路。这条要认。

### 这一版怎么修

**不是修回传，是补一条入口：**

- 「刚拍的这一张」标题右侧新增 **[从机身取最新]** 按钮。
- 点了之后：停取景 → 读每个存储卷的对象句柄表 → 从尾部倒序取 4 个 → 取第一个能下载的 → 解码 → 恢复取景。
- 相机的对象句柄是按拍摄顺序递增的，尾部就是最新的，所以只读 4 个就够，不会像全卡遍历那样慢。
- 空态文案也改了，直接把两条路的区别写在界面上：
  ```
  还没有取回照片
  点上面的黄环快门 → 走 0x9207 拍摄
  用机身按键拍的照片，点右上「从机身取最新」
  ```

**两条路现在都通：**
- 点 App 里的黄环快门 → `0x9207 → 0xC101 → 0x1009`。
- 用机身按键拍 → 拍完点「从机身取最新」。

## 二、为什么「下发」报 `0x500E AccessDenied`

### 你自己截的「属性」面板就是答案

```
曝光程序 0x500E   只读   当前=03 00    GetSet=只读
ISO 0x500F        可写   当前=A0 00    GetSet=读写
光圈 0x5007       可写   当前=5E 01    GetSet=读写
快门(标准) 0x500D  只读   当前=4D 01 00 00    GetSet=只读
快门(尼康) 0xD100  只读   当前=1E 00 01 00    GetSet=只读
曝光补偿 0x5010    可写   当前=00 00    GetSet=读写
白平衡 0x5005     可写   当前=02 00    GetSet=读写
优化校准项 0xD200  可写   当前=C9 00    GetSet=读写
```

`GetSet` 是机身自己在 `0x1014` 描述符里声明的权限，**不是猜的、不是错误码推断的**。

**Z30 明确声明：档位和快门这三条是只读属性。** 所以：

- 不是取景锁住了（v1.6.2 加「停取景 + 重试 5 次」注定无效，白改）。
- 不是瞬时错误（重试一万次还是 `AccessDenied`）。
- 就是这台相机的 PTP 接口**不允许远程拨档、不允许远程改快门**。

### 这一版怎么改

1. **[属性] 的结论被记下来了**：点过一次「属性」之后，那几个只读属性码缓存进 `readOnlyProps`，后续所有下发都按它执行。
2. **下发时直接跳过，不再报错**：
   - 跳过的会写进「跳过：」一栏，例如
     `曝光程序（0x500E 机身只读，请在相机上拨）`
     `快门（0xD100/0x500D 机身只读，请在相机上拨）`
   - 这样「部分参数失败」里就不会再出现一条你根本解决不了的错误。
3. **档位 chip 点了不再白发一次**：直接提示
   `机身不允许远程拨档，请在 Z30 上转模式盘（界面已按 A 档显示）`，界面上的档位只是显示预期，不会误导你以为已经切过去了。
4. **滑杆禁掉**：快门滑杆在只读状态下一律变灰（原本只有 P/A 档才灰）。

### 现在「下发」实际能改的

| 参数 | 能不能远程写 |
|---|---|
| ISO | ✅ |
| 光圈 | ✅（M/A 档；S 档由机身配） |
| 曝光补偿 | ✅ |
| 白平衡 | ✅ |
| 优化校准项 | ✅ |
| **曝光程序（M/P/A/S）** | ❌ 机身只读，只能在相机上转盘 |
| **快门速度** | ❌ 机身只读，只能在相机上拨 |

## 三、顺手修的一个日志噪声

`CloseSession 0x1003` 之前带了一个 sessionID 参数，Z30 每次都回 `0x2006 ParameterNotSupported`：

```
[21:59:01.743] CMD 0x1003 params=[0x1]
[21:59:01.xxx] RESP 0x2006 ParameterNotSupported
```

ISO 15740 规定 CloseSession 不带参数。已改成空参数，以后断开连接不会在日志里留一条假错误。

## 五、测试顺序

1. 装 v1.6.4，接上 Z30，等「会话已建立」。
2. 进「监看」→ 曝光参数点一次 **[属性]**。（只有点过它，App 才知道哪些属性是只读的）
3. 看下面的灰字：应该出现「机身声明 0x500E 只读 —— 档位只能在 Z30 上转盘」。
4. 改 ISO / 光圈 → 点 **[下发]**。应该提示「参数已下发（n 项写入，m 项跳过）」，跳过栏里是曝光程序和快门。
5. **用机身快门按键拍一张** → 回到 App 点 **[从机身取最新]** → 应该几秒内出图，并显示「已取回机身最新一张 · 分辨率 · 大小」。
6. 点图开全屏，双指缩放看细节。

## 六、仍未验证 / 已知限制

- 「从机身取最新」的下载速度取决于相机 USB 传输速度，一张 24MP JPEG 大约 2–5 秒，没有进度条（下一步可以补）。
- 如果存储卡里最后几个对象是视频，会跳过继续往前找照片；但如果最近 4 个全是视频，会取不到。真遇到就把这个数调大。
- 档位和快门**在 Z30 上确实没法远程改**。这不是我们能修的，是机身固件限制。若以后要「按配方自动切档」的需求，只能提示用户手动转盘。
- 拍摄链路（`0x9207`）这次日志里没有样本，所以 v1.6.2 那套改动到底对不对，还得你点一次 App 里的黄环快门才算验证过。
